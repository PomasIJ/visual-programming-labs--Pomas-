# Pomas_Lab_7

## Архитектура данных

Модель разделена на шесть связанных баз данных: профили, роли пользователей, темы, занятия, домашние задания и уведомления. Каждая таблица имеет системный автоинкрементный `ID`; основной заголовок Notion остаётся обязательным для каждой базы.

## Связи

- Профили ↔ Роли пользователей: у записи роли один профиль; в профиле предусмотрена связь максимум с одной ролью.
- Профили ↔ Темы: тема может быть персональной для одного ученика; связь в профиле показывает его темы.
- Темы ↔ Занятия: занятие связано с одной темой.
- Профили ↔ Занятия: занятие связано с одним учеником.
- Занятия ↔ Домашние задания: задание связано с одним занятием.
- Профили ↔ Домашние задания: задание связано с одним учеником.
- Профили ↔ Уведомления: уведомление адресовано одному пользователю.

## Формула для просрочки ДЗ

Добавлена в базу «Домашние задания» как текстовая формула `Overdue_check`: пустой срок → «No due date»; статус `reviewed` или `submitted` показывает соответствующее состояние; иначе срок раньше сегодняшнего дня → «Overdue», в остальных случаях → «On time».

## Вариант кнопки

В базе «Занятия» можно добавить кнопку `Завершить занятие` с действием изменения `Status` на `completed`. Конфигурация действия задаётся в редакторе кнопок Notion; кнопки базы данных позволяют редактировать свойства записи. [[1]](https://www.notion.so/help/guides/make-work-more-efficient-database-button-property)

## Ограничения модели

- Ограничение связи «не более одной» не обеспечивает уникальность: Notion может позволить создать несколько записей ролей для одного профиля. Поддерживайте одну активную роль вручную.
- `Grade` — числовое поле; диапазон 1–10 не валидируется автоматически.
- `Created_at` в профилях заполняется системным временем создания страницы; `Created_at` в уведомлениях остаётся датой, которую можно задать при создании уведомления.
